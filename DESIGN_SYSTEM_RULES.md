# Design System Rules for Move-Mint App

This document provides comprehensive guidelines for integrating Figma designs using the Model Context Protocol (MCP) in the Move-Mint codebase.

---

## 1. Design System Structure

### Token Definitions

**Location**: Design tokens are defined in `/src/styles/globals.css`

**Format**: CSS Custom Properties (CSS Variables) defined in `:root` and `.dark` selectors

**Key Token Categories**:

```css
/* Color Tokens */
--background, --foreground
--card, --card-foreground
--popover, --popover-foreground
--primary, --primary-foreground
--secondary, --secondary-foreground
--muted, --muted-foreground
--accent, --accent-foreground
--destructive, --destructive-foreground
--border, --input, --ring
--switch-background, --switch-background-checked
--switch-thumb, --switch-thumb-checked
--sidebar-*, --chart-*

/* Spacing & Layout */
--spacing: .25rem  /* Base spacing unit */
--container-sm: 24rem
--container-md: 28rem
--container-lg: 32rem

/* Typography Tokens */
--text-xs to --text-4xl (with line-height)
--font-weight-normal: 400
--font-weight-medium: 500
--font-weight-semibold: 600
--font-weight-bold: 700

/* Border Radius */
--radius: 0.625rem  /* Base radius */
--radius-sm: calc(var(--radius) - 4px)
--radius-md: calc(var(--radius) - 2px)
--radius-lg: var(--radius)
--radius-xl: calc(var(--radius) + 4px)

/* Animation & Transitions */
--ease-out: cubic-bezier(0, 0, .2, 1)
--ease-in-out: cubic-bezier(.4, 0, .2, 1)
--default-transition-duration: .15s
```

**Theme System**: The project uses a light/dark theme system with:
- Default theme: Dark mode with purple gradient background (#000000 to #4B0082)
- Light theme: Gray gradient background (#6b7280 to #4b5563)
- Theme toggling via `.dark` and `.light` classes on `documentElement`

**Color System**:
- Primary brand color: `#3EB489` (teal/mint green) in dark mode, `#2d8a68` in light mode
- Secondary: Purple tones (`#4B0082`)
- Uses `oklch()` color space for Tailwind color utilities

## 2. Component Library

### Location
- **UI Components**: `/src/components/ui/`
- **Feature Components**: `/src/components/`

### Component Count
- 49+ pre-built UI components in `/src/components/ui/`
- Custom feature components in `/src/components/`

### Component Architecture

**Base Pattern**: Radix UI primitives + Class Variance Authority (CVA) + Tailwind CSS

**Example Component Structure** (Button):

```tsx
import { Slot } from "@radix-ui/react-slot@1.1.2";
import { cva, type VariantProps } from "class-variance-authority@0.7.1";
import { cn } from "./utils";

const buttonVariants = cva(
  // Base classes
  "inline-flex items-center justify-center...",
  {
    variants: {
      variant: { default, destructive, outline, secondary, ghost, link },
      size: { default, sm, lg, icon }
    },
    defaultVariants: { variant: "default", size: "default" }
  }
);

function Button({ className, variant, size, asChild, ...props }) {
  const Comp = asChild ? Slot : "button";
  return <Comp className={cn(buttonVariants({ variant, size, className }))} {...props} />;
}
```

**Key Component Categories**:
- **Forms**: Input, Checkbox, Radio, Select, Switch, Label, Form
- **Layout**: Card, Sheet, Dialog, Drawer, Popover, Separator, ScrollArea
- **Navigation**: NavigationMenu, Menubar, ContextMenu, DropdownMenu, Breadcrumb, Tabs
- **Feedback**: Alert, Badge, Progress, Skeleton, Tooltip, HoverCard
- **Data Display**: Table, Calendar, Carousel, Chart, Avatar
- **Advanced**: Sidebar, Resizable, Command, InputOTP

### Utility Function

**Location**: `/src/components/ui/utils.ts`

```tsx
import { clsx, type ClassValue } from "clsx";
import { twMerge } from "tailwind-merge";

export function cn(...inputs: ClassValue[]) {
  return twMerge(clsx(inputs));
}
```

**Usage**: Always use `cn()` for className merging to ensure proper Tailwind class deduplication.

```tsx
import { CalendarDays, Flame, Target, Users } from 'lucide-react';
```

### Icon Naming & Conventions
- Use PascalCase imports from lucide-react
- Common size classes: `size-4` (16px), `size-5` (20px), `size-6` (24px)
- Icons inherit text color by default, use text-* utilities for custom colors

### Icon Integration with Components
- UI components have built-in icon support (see Button component)
- SVG icons automatically sized via `[&_svg]:size-4` type selectors

### Figma MCP Icon Rules
- When Figma MCP provides SVG assets via localhost, use those directly
- DO NOT install additional icon packages if assets are in Figma payload
- Store Figma-provided SVG icons in `/src/assets/` and import as React components or inline SVG

## 6. Styling Approach

### CSS Methodology
- **Tailwind CSS utility-first** approach
- **CSS Modules**: Not used
- **Styled Components**: Not used
- **Inline styles**: Minimal usage (only for dynamic values like gradients)

### Style Organization

1. **Global Styles**: `src/styles/globals.css`
   - Theme tokens (`:root` and `.dark`)
   - Base typography
   - Theme-specific overrides

2. **Tailwind Base Styles**: `src/index.css`
   - Generated by Tailwind v4
   - Contains `@layer properties`, `@layer theme`, `@layer base`

3. **Component Styles**: Inline Tailwind classes via `className`

### Responsive Design
- **Mobile-first approach**
- Max-width container: `max-w-md mx-auto` (typically 448px)
- Uses Tailwind responsive prefixes: `sm:`, `md:`, `lg:`, `xl:`
- Container queries: `@container/card-header` for advanced responsive patterns

### Dark Mode Implementation
```tsx
// Toggle dark mode
document.documentElement.classList.toggle('dark', isDarkMode);
document.documentElement.classList.toggle('light', !isDarkMode);
```

- Use `dark:` prefix for dark mode styles
- Custom dark variant: `@custom-variant dark (&:is(.dark *));`

### Key Styling Patterns

**1. Component Base Classes**
```tsx
className="inline-flex items-center justify-center gap-2 rounded-md..."
```

**2. Conditional Styling with cn()**
```tsx
className={cn(baseClasses, conditionalClasses, className)}
```

**3. State-based Styling**
```tsx
className="hover:bg-accent focus-visible:ring-ring/50 disabled:opacity-50"
```

**4. Color Token Usage**
```tsx
// Use semantic color names, not raw values
className="bg-primary text-primary-foreground"  // ✓ Good
className="bg-[#3EB489] text-white"             // ✗ Avoid
```

## 8. Figma MCP Integration Rules

### Workflow

**Step 1**: Fetch Design Context
```
Use mcp__figma__get_design_context with nodeId and fileKey
```

**Step 2**: Get Visual Reference
```
Use mcp__figma__get_screenshot for the same nodeId
```

**Step 3**: Download Assets
```
If Figma MCP returns localhost asset URLs, use them directly
Store assets in /src/assets/ if needed
```

**Step 4**: Translate to Project Conventions

**From Figma/Tailwind Output:**
```tsx
<div className="bg-[#3EB489] text-white px-4 py-2 rounded-lg">
  Button
</div>
```

**To Project Style:**
```tsx
import { Button } from '@/components/ui/button';

<Button variant="default" size="default">
  Button
</Button>
```

### Translation Rules

1. **Replace Hardcoded Colors**
   - `bg-[#3EB489]` → `bg-primary`
   - `text-white` → `text-primary-foreground`
   - `bg-[#4B0082]` → `bg-secondary`

2. **Use Existing Components**
   - Raw `<button>` → `<Button>` from ui/button
   - Raw `<input>` → `<Input>` from ui/input
   - Raw cards → `<Card>` compound components

3. **Preserve Design Tokens**
   - Border radius: Use `rounded-lg` (matches `--radius`)
   - Spacing: Use Tailwind spacing scale (matches `--spacing` base)
   - Typography: Use `text-sm`, `text-base`, `text-lg` (matches `--text-*` tokens)

4. **Component Patterns**
   ```tsx
   // Figma output with Tailwind
   <div className="flex flex-col gap-4 p-6 bg-card rounded-xl border">
     <h3 className="text-lg font-medium">Title</h3>
     <p className="text-sm text-muted-foreground">Description</p>
   </div>

   // Translate to project pattern
   <Card>
     <CardHeader>
       <CardTitle>Title</CardTitle>
       <CardDescription>Description</CardDescription>
     </CardHeader>
   </Card>
   ```

5. **Icon Handling**
   - Use Lucide React icons when possible
   - Import Figma SVG assets to `/src/assets/` for custom icons
   - Do NOT install new icon packages

6. **Responsive Behavior**
   - Maintain mobile-first approach
   - Use `max-w-md mx-auto` for content containers
   - Test at 375px (mobile) and 768px (tablet) viewports

### Validation Checklist

- [ ] Colors match design tokens (no hardcoded hex values)
- [ ] Uses existing UI components from `/src/components/ui/`
- [ ] Typography uses semantic classes (`text-sm`, `font-medium`, etc.)
- [ ] Spacing uses Tailwind scale (px-4, gap-2, etc.)
- [ ] Icons from Lucide React or Figma assets
- [ ] Responsive on mobile (375px) and tablet (768px)
- [ ] Dark mode variant tested with `.dark` class
- [ ] Accessibility: proper ARIA labels, keyboard navigation
- [ ] Visual parity confirmed against Figma screenshot

## 10. DO's and DON'Ts

### DO

- ✓ Use semantic color tokens (`bg-primary`, not `bg-[#3EB489]`)
- ✓ Import components from `/src/components/ui/`
- ✓ Use `cn()` utility for className composition
- ✓ Follow mobile-first responsive design
- ✓ Test both light and dark themes
- ✓ Use Lucide React for icons
- ✓ Extract reusable components to `/src/components/ui/`
- ✓ Use TypeScript interfaces for props
- ✓ Follow Radix UI patterns for accessible components
- ✓ Use CVA for component variants

### DON'T

- ✗ Hardcode colors (use theme tokens)
- ✗ Create new icon libraries (use Lucide React)
- ✗ Use inline styles for static values
- ✗ Duplicate existing UI components
- ✗ Skip dark mode testing
- ✗ Use `className` string concatenation (use `cn()`)
- ✗ Create CSS modules or styled-components
- ✗ Skip accessibility attributes
- ✗ Ignore Figma spacing/sizing in designs
- ✗ Use `any` type in TypeScript

## 11. Code Snippets

### Creating a New UI Component

```tsx
import * as React from "react";
import { cva, type VariantProps } from "class-variance-authority@0.7.1";
import { cn } from "./utils";

const myComponentVariants = cva(
  "base-classes-here",
  {
    variants: {
      variant: {
        default: "variant-classes",
        secondary: "variant-classes",
      },
      size: {
        default: "size-classes",
        sm: "size-classes",
      },
    },
    defaultVariants: {
      variant: "default",
      size: "default",
    },
  }
);

interface MyComponentProps
  extends React.HTMLAttributes<HTMLDivElement>,
    VariantProps<typeof myComponentVariants> {}

function MyComponent({ className, variant, size, ...props }: MyComponentProps) {
  return (
    <div
      className={cn(myComponentVariants({ variant, size, className }))}
      {...props}
    />
  );
}

export { MyComponent, myComponentVariants };
```

### Using Theme Tokens

```tsx
// In component
<div style={{
  background: 'var(--background)', // Use CSS variable for dynamic values
}} className="text-foreground">

// OR prefer Tailwind classes
<div className="bg-background text-foreground">
```

### Importing Assets

```tsx
import logoImage from '@/assets/logo.png';

<img src={logoImage} alt="Logo" className="size-12" />
```

## 12. Accessibility Guidelines

- Use semantic HTML (`<button>`, `<nav>`, `<main>`, etc.)
- Include `aria-label` for icon-only buttons
- Ensure color contrast meets WCAG 2.1 AA standards (4.5:1 for text)
- Support keyboard navigation (Tab, Enter, Escape)
- Use Radix UI components for built-in accessibility
- Test with screen readers (NVDA, JAWS, VoiceOver)
- Include focus-visible styles: `focus-visible:ring-ring/50`

## Summary

This design system is built on:
- **React + TypeScript + Vite** for fast development
- **Tailwind CSS v4** with semantic design tokens
- **Radix UI + CVA** for accessible, variant-driven components
- **Lucide React** for iconography
- **Mobile-first responsive design** with dark mode support

When integrating Figma designs, always translate raw Tailwind output to use the existing component library and design tokens. Maintain consistency with the established patterns, and validate against both visual design and accessibility standards.
